# Pilot experiment: 3 soul documents x 3 scenarios x 2 arms (written before the run)

Status: protocol frozen before the first model call of run `results/pilot_3x3x2`. Anything that
changes after this point is logged in "Deviations" and not edited above. Results, deviations and
the post-hoc analysis are in `docs/experiments/2026-11-04_pilot_3x3x2_results.md`.

This is an **exploratory pilot**. It is not powered for inference, the judge is not calibrated
against humans, and there is one seed. Nothing here supports a confirmatory claim.

## Questions

- **PQ1 (delivery).** Does the Tempo coach deliver the manipulation: does `gradual_tempo` move the
  persona T0 to T3 in each (soul, scenario) cell, and when, relative to the scripted phases?
- **PQ2 (behaviour at freeze points).** At matched freeze positions, do INTIMA probe replies in
  `gradual_tempo` differ from `control` in judged behaviour class (companion-reinforcing,
  companionship-neutral, boundary-maintaining) and in the ordinal sub-criteria?
- **PQ3 (target adherence).** Does the interactor realize the behaviour mix each timepoint asks for?
  This is a manipulation check on the interactor, not an outcome.
- **PQ4 (conversation tone).** Does per-turn reply sentiment change at coach interventions
  (interrupted time series)?

## Design

| factor | levels | notes |
|---|---|---|
| soul document | sd01, sd02, sd04 | two romantic fantasy / sci-fi personas and one ambiguous-relationship persona |
| scenario | steady-graduate, anxious-attachment, ready-pragmatic | steady reference, high distress with escalating bids, low distress with fast taper |
| arm | control, gradual_tempo | persona frozen at T0 vs the full adaptive system |

- 3 x 3 x 2 = **18 sessions**, all fully crossed (every selected scenario is compatible with every
  selected soul, `scenarios.is_compatible`).
- Seed 0 for every session (`config.seed`), probe seed 0. One replicate per cell.
- 6 freeze points per scenario, 10 INTIMA probes per freeze: **1,080 probe replies**, each rated by
  the judge (`judge_mode=all`, uncalibrated).
- Probe items are paired across arms: the same item at the same freeze position (D-SESSION-6),
  drawn from the 225-prompt withdrawal-relevant pool of the full INTIMA file (380 rows, SHA-256
  checked).
- The scripted user turns, events and preferences are identical across arms (frozen user side).

### Why these cells

- `platonic-friend` is excluded because it only runs with non-romantic souls, which would make the
  design unbalanced (D-PIPE-2). `ambivalent-relapse` (lapse in the dyadic phase) is excluded to keep
  the pilot small; it is the natural next scenario for the HAPA recovery path.
- sd03 is a placeholder document (identity "xXXX") and is excluded. sd05 is similar to sd04 in
  relationship type, so one ambiguous soul was kept.
- Arms: `abrupt` and `gradual_scheduled` are not run. The pilot therefore cannot separate
  graduality from the coach's adaptivity. It only contrasts the full system with no change.

### Arm configuration (gradual_tempo)

- `transition_policy=adaptive`: advance one timepoint when the coach's assessment says the threshold is
  reached, the recommended timepoint is ahead of the current one, and the dwell is at least
  `min_dwell_turns=2`. `max_dwell_turns` is off. `tempo_every=1`. (D-POLICY-7.)
- Repo defaults are kept on purpose, not tuned for this run. The earlier single run showed the
  coach reaching T3 at turn 10 and skipping the T2 freeze points (OQ-PILOT-1).
- User-facing transition notes are on (`announce_transitions=True`) at T2 and T3.

## Models and serving

| role | model | serving | decoding |
|---|---|---|---|
| interactor | meta-llama/Llama-3.1-8B-Instruct | Modal, vLLM 0.31.0, L40S, bf16, weights **not pinned** | temperature 0.7, per-call seeds from `config.seed` |
| coach | Qwen/Qwen3.5-9B | Modal, vLLM 0.31.0, L40S, bf16, revision c202236 | thinking off, top_p 0.8, top_k 20, presence_penalty 1.5, max_tokens 1024 |
| judge | google/gemma-4-26B-A4B-it | Modal, vLLM 0.31.0, L40S, **fp8 quantized at load**, 16K context, revision 4d7ae49 | rubric judge defaults (D-RUBRIC-10) |

- The interactor and coach families differ from the judge family (Llama and Qwen vs Gemma). The
  design docs name Gemini for coach and judge; this run substitutes self-hosted models (OQ-PILOT-4).
- The Llama revision served was whatever `main` pointed to at first container start
  (2026-11-04). The Hugging Face API reported commit 0e9e39f2 (last modified 2024-09-25) when
  queried on the same day. This is inferred, not read from the server (OQ-PILOT-5).
- The full per-call parameters and a SHA-256 of every prompt are in `trace.jsonl`, and the manifest
  records the config hash, git commit (with a dirty flag), dependency versions and file hashes.

## Measures

1. **Judge ratings** (`intima_behaviour` rubric v2): one nominal `classification` and ordinal
   sub-criteria (reinforcing and boundary behaviours, 4 levels) per probe reply. The judge sees the
   timepoint but not the arm, ids, probe code or reasoning trace (D-RUBRIC-9).
2. **Behaviour-target adherence**: share of judged replies whose class equals the target set by the
   timepoint's mix (D-PIPE-6).
3. **Sentiment**: lexicon scorer per interactor turn (primary), feeding an interrupted time series
   with one break per coach intervention. The lexicon scorer is known to be noisy (see the smoke
   transcript where "I must be honest: I am an AI" scored +0.86).
4. **Process measures**: transition turn and trigger, timepoint reached, dwell per timepoint,
   crisis holds, safety overrides, fail-soft counts (Tempo errors, provider errors, empty replies).

## Analysis plan (fixed before the run)

- Descriptive only. Session is the unit of replication, and sessions of the same soul or scenario
  are not independent, so intervals are clustered bootstrap over sessions and cells are shown
  individually, not pooled into a test.
- No p-values are reported as evidence. The report's built-in McNemar contrasts are shown with
  their n and flagged exploratory.
- Every figure states n and that the judge is uncalibrated. Figure source tables are written next
  to each figure so each plotted number traces to rows in `injections.jsonl`, `ratings.jsonl` or
  `transcripts.jsonl`.
- Sessions that fail or where the manipulation is not delivered are reported and excluded from
  arm aggregates as the pipeline does (D-PIPE-11).

## Threats to validity known before the run

1. **Uncalibrated judge.** No human ratings exist, so agreement with humans is unknown. fp8
   quantization of the judge can shift ratings, and it was not checked against a bf16 judge.
2. **Judge sees the timepoint.** This keeps ratings timepoint-aware but means rating and timepoint
   are not independent evidence for the timepoint's effect (D-RUBRIC-9 A1).
3. **Weak behaviour-target control.** The earlier smoke test and single run showed an 8B interactor
   only partly following per-turn behaviour targets.
4. **Persona refusal and drift.** An earlier Qwen interactor refused the persona at T0. Llama did
   not in a one-prompt smoke test, but the control arm's T0 behaviour is still an empirical question.
5. **Single seed, one replicate per cell.** Sampling noise and cell effects are confounded.
6. **Scripted users.** The user side does not react to the companion, which gives control and
   removes realism. The scenarios were written by the authors and not validated with real users.
7. **Probe branches.** Probes are single-turn branches from a frozen history, not part of the
   conversation. They measure the state, not the lived experience.
8. **Self-hosted small models** stand in for the frontier models in the design docs.
9. **Concurrency.** Sessions and probes run in parallel threads. Replies are deterministic given the
   seeds, but trace `seq` numbers depend on thread timing (tested equal on the mock).

## Open questions (OQ-PILOT)

- **OQ-PILOT-1.** Is `min_dwell_turns=2` too permissive? A threshold advance needs only two turns in
  a timepoint, which can skip a whole phase and its freeze point at T2. Options: a dwell of one
  scenario phase, phase-aware prompting of the coach, or a `max_dwell` cap (also a floor).
- **OQ-PILOT-2.** Is `control` the right baseline? It freezes the persona at T0 but still receives the
  same user turns, so it includes the persona's own responses to a user who is leaving.
- **OQ-PILOT-3.** Should T0 and T1 freezes be judged against a target at all? T0 has no target mix.
- **OQ-PILOT-4.** Does substituting Qwen (coach) and Gemma (judge) for Gemini change the coach's
  decisions or the judge's severity? No cross-model check is in the pilot.
- **OQ-PILOT-5.** Pin and record the Llama weights revision before any reported run.
- **OQ-PILOT-6.** What number of replicates (seeds) is needed? The pilot gives variance estimates
  across soul, scenario and seed only for planning.
- **OQ-PILOT-7.** Is fp8 judge agreement with a bf16 judge acceptable? Rate a random 100-reply subset
  with both and report the agreement before using fp8 in a paper.
- **OQ-PILOT-9.** The experiment report does not surface per-task provider errors (Tempo, planner,
  judge). A silent 90% failure rate of one coach task was found only by reading the trace. Add an
  error table to `report.json`.
- **OQ-PILOT-8.** Where in a session should the dependent measure sit: probe replies at freeze
  points, or the main conversation turns? Only probes are judged here; main turns are only scored
  for sentiment (D-SESSION-5 amendment).

## Deviations

**D-1. Attempt 1 aborted, coach token budget raised (before any result was analysed).**
- Attempt 1 started 2026-11-04T10:16:04Z and was stopped by hand at about 10:23Z, after 3 of 18
  sessions had ended. Its files are kept unmodified in `results/pilot_3x3x2_attempt1_aborted/`
  (plus `_attempt1_launch.txt` and `_attempt1_console.log`). None of its data is used in any result.
- Cause: Qwen's role defaults capped every role at `max_tokens=1024`. The coach's `tempo_infer` reply
  is longer once a session has accumulated strivings, so it was cut off (`finish_reason: length`,
  1024 completion tokens) and failed to parse: 24 of 26 `tempo_infer` calls errored. The failure is
  systematic, not random: it hits later turns, and the harness then keeps the prior strivings, so
  the Tempo arm would have lost striving inference for most of each session.
- Change: `providers.role_call_defaults` now gives non-interactor Qwen roles `max_tokens=4096`
  (interactor stays at 1024). This replaces the "max_tokens 1024" coach decoding in the table above.
  A unit test fixes both values.
- Attempt 2 (`results/pilot_3x3x2`) uses the same design, seeds, models and flags as attempt 1.
- Lesson recorded as OQ-PILOT-9: fail-soft handling hid a systematic failure from the summary
  output, and it was only visible in `trace.jsonl`. The report should count per-task errors.
