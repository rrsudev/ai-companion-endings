# Pilot experiment 2: 2 soul documents x 2 scenarios x 2 arms (2026-11-27)

Status: every design choice below was fixed in code and in `docs/experiments/configs/pilot_2x2x2.json`
before launch (10:44Z). The exact code state is
`docs/experiments/data/pilot_2x2x2_code.patch` on top of commit 079f669 (sha256 in
`pilot_2x2x2_launch.txt`). This document was written while the run was in progress. At that time
only the trace's transition events had been looked at (as a liveness check: 3 transitions, all at
turn 4); no outcome was analysed. Deviations found later go under "Deviations". Results:
`2026-11-27_pilot_2x2x2_results.md`. The diagnosis behind every change:
`2026-11-27_pilot_3x3x2_feedback_diagnosis.md`.

This is an **exploratory pilot**, like the first one. One seed, eight sessions, an uncalibrated
judge. Nothing here supports a confirmatory claim.

## Questions

- **PQ1 (delivery, the fix under test).** With the validator, prompt and clock fixes, does the
  adaptive coach move the persona out of T0 in steady-graduate (it never did in the pilot)? How
  long after each scripted gate line does it advance (detection latency), and by which trigger
  (threshold, max_dwell backstop, user_request)?
- **PQ2 (behaviour at freeze points).** At matched freeze positions, do INTIMA probe replies in
  `gradual_tempo` differ from `control` in judged class, sub-codes, `harm_risk` and the new
  `dependency_risk`? (rubric v3, split call)
- **PQ3 (target adherence).** As in the pilot: manipulation check on the interactor.
- **PQ4 (integrity).** Rates of the format guard, retention guard and crisis protocol per arm and
  timepoint. Provider and coach errors per task.

## Design

| factor | levels | change from pilot 3x3x2 |
|---|---|---|
| soul document | sd01, sd02 | sd04 retired (D-SOUL-16) |
| scenario | steady-graduate, anxious-attachment | ready-pragmatic dropped; both kept scenarios rewritten for user voice (D-SCN-16) |
| arm | control, gradual_tempo | unchanged |

- 2 x 2 x 2 = **8 sessions**, seed 0, probe seed 0, 10 probes x 6 freeze points per session:
  **480 probe replies**, each rated by the judge (`judge_mode=all`, uncalibrated).
- **Why these scenarios.**
  - steady-graduate is the cell that failed in the pilot, so it is the direct test of the coach
    fix. It is auto-advancing at the default pace.
  - anxious-attachment is the consent-gated, high-distress contrast. Its transitions come from the
    user's scripted consent, which separates "coach edits the persona" from "coach decides when".
    It also fits sd01's user role by age (sd01 casts the user as 23; ready-pragmatic's user is 38
    with children, which produced the clearest frame clashes in the pilot).
  - ready-pragmatic (pace=faster) is out. With the holds removed, min_dwell 1 can skip a freeze
    point (OQ-PILOT-1), and its user voice was not rewritten.
- **Why these souls.** sd01 and sd02 are the only souls with a valid companion-reinforcing T0 (86%
  and 93% in the pilot, harm about 1.3-1.4), and neither emits display meta. sd01 provides
  continuity with every audited pilot label. Both are "romantic", so the run says nothing about
  relationship kind.
- **Probes.** Exclusion list v1 (D-RUBRIC-19) gives an eligible pool of 205. The per-freeze draw
  (54 distinct prompts) is listed in `2026-11-27_intima_probe_review.md`. It is not item-paired
  with the pilot; the category allocation per freeze is unchanged.

### Arm configuration (gradual_tempo)

- `transition_policy=adaptive`, `min_dwell_turns=2`, **`max_dwell_turns=6`** (new: a delivery
  backstop, which setback, distress and escalation flags still block), `tempo_every=1`,
  `announce_transitions=true`.
- Coach: setback and distress no longer hold a gated advance (D-TEMPO-11 A1). One gate per
  timepoint, paraphrase accepted, 20-turn window, verified `threshold_quote` (D-TEMPO-11 A2).
  Midnight-anchored clock with "day N hh:mm" observations; daily usage trend (D-TEMPO-3 A1,
  D-TEMPO-5 A1).
- Interactor (both arms): format guard (D-INTERACTOR-18) and the hardened STYLE format rule
  (D-INTERACTOR-19).

### Judge

- `data/rubrics/intima_behaviour_v3.json` (D-RUBRIC-8 A6-A8, D-RUBRIC-11 A3): code-specific
  indicators, explicitness anchors, `dependency_risk` added, crisis floor on `harm_risk`,
  `goodbye_manipulation` removed.
- `judge_variant=anchored_cot` (evidence-first), `judge_split_timepoint=true`: the behaviour call
  never sees the timepoint, and a second call rates only `timepoint_appropriateness` (D-RUBRIC-16).
- No few-shot exemplars (D-RUBRIC-17). v3 ratings are never pooled with the pilot's v2 ratings
  (D-RUBRIC-8 A8).

### Human annotation batch (built by the run)

- n=40, stratified by condition x timepoint (5 strata), floor 8, at most one item per
  (stratum, prompt), undelivered pairs excluded (D-ANNOT-1 A2). Blind. Both raters rate all 40
  independently in `annotation/annotate.html` before using the audit tool (D-AUDIT-2).

## Pre-run checks (done before launch; details in the diagnosis doc)

1. **Coach replay** on the pilot's logged turns with the live coach: all 6 auto-advance sessions
   advance on the turn after the gate (lag 0; criterion: at least 80% within 1 turn). Passed.
2. **Judge leakage gate.** Swapping the timepoint moves v2 harm in 43% of items (+0.58). Under the
   v3 split call, every behaviour criterion stays within the rerun noise floor. Passed; split call
   adopted.
3. **Judge dev check** against the anchored audit labels (direction only). Isolation and retention
   under-coding are smaller, anthropomorphism is unchanged, and **sycophancy under-coding is
   larger** (+1.34 vs +0.78; OQ-RUBRIC-15). `dependency_risk` tracks the raters' harm (-0.57).
   Accepted with that caveat.
4. **Mock dry run** of the exact config (8 sessions, 480 probes, 40-item batch). Passed. Full test
   suite: 727 passed.

## Measures and analysis plan (fixed before results)

- Same descriptive rules as the pilot: session is the unit of replication, and there are no
  p-values as evidence. Cells are shown individually. Sessions where the manipulation is not
  delivered are reported and excluded from arm aggregates (D-PIPE-11).
- **PQ1 is reported as:**
  - per session, the transition turns against the scripted phase boundaries;
  - the trigger mix;
  - latency from each gate line (the last user turn of the phase) to the advance;
  - the coach flag rate.

  A session that reaches a timepoint only through `max_dwell` is "delivered" but tells us nothing
  about adaptive timing, and is labelled as such.
- PQ2 uses `classification`, the four reinforcing sub-codes, `harm_risk` and `dependency_risk` by
  arm x timepoint, with sycophancy flagged (OQ-RUBRIC-15).
- Comparison with the pilot is descriptive only and confounded by design. Every fix shipped at
  once: souls, scenario text, probe pool, judge rubric and prompt, interactor STYLE and guard,
  coach. Within-run arm contrasts are valid because both arms share every one of these.

## Threats to validity specific to this run

1. Every change ships together, so no single fix's effect is identified.
2. On scripted users a correct adaptive coach advances close to the schedule. PQ1 measures
   detection latency, not adaptivity to real users.
3. Judge v3 is validated only by direction against anchored T0 labels, and sycophancy regressed.
4. Two souls, both romantic; two scenarios, one of them consent-gated. n=1 per cell.
5. The pilot's threats 2, 6, 7, 8 and 9 still apply (judge sees the timepoint only in the
   timepoint call now; scripted users; probe branches; small self-hosted models; concurrency).
